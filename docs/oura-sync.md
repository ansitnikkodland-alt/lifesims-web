# Oura Ring → LifeSims 3D

## Настройка OAuth

Oura поддерживает клиентский OAuth2 с `response_type=token` и отдельный серверный OAuth2. LifeSims использует клиентский вариант без Client Secret, чтобы не раскрывать секрет в открытом HTML/PWA. Источник: https://cloud.ouraring.com/docs/authentication

1. В аккаунте Oura Cloud → My Applications зарегистрируй приложение.
2. Укажи разрешённый Redirect URI **точно** `https://ansitnikkodland-alt.github.io/lifesims-web/scene/`.
3. Скопируй **Client ID**, но **не Client Secret**.
4. В LifeSims → «Потребности» → «Oura Ring» вставь Client ID и нажми «Подключить Oura». Oura запросит только scope `daily` (сон, активность и восстановление).
5. После возвращения в LifeSims нажми **«Проверить данные»**, посмотри предварительный просмотр и **«Сохранить в LifeSims»**.
6. Для дальнейших проверок можно включить опцию «Обновлять при открытии LifeSims». Проверки идут не чаще одного раза в 6 часов, **только пока вкладка приложения открыта с действующей авторизацией**.

Не публикуй Client Secret, access token или адрес с фрагментом `#access_token=...` в чате, репозитории или скриншоте.

## Данные и источники

Используется Oura API V2: https://cloud.ouraring.com/v2/docs.

- `sleep.total_sleep_duration` (секунды фактического сна) → `days[day].sleepHours` (сумма всех периодов сна кроме записей типа `rest`, округление до 0,01 ч).
- `daily_activity.steps` → `days[day].steps`.
- `daily_activity.total_calories` → `days[day].totalCalories`. Это **общий** расход калорий по Oura, а не только активные калории или съеденная пища.
- `daily_sleep.score`, `daily_readiness.score`, `daily_activity.score` → `days[day].ouraScores`. Они сохраняются отдельно от игровой потребности во сне, настроения и ресурса.
- LifeSims по-прежнему считает потребность во сне из фактического сна и накопленного долга, ориентир 7,5 ч/сутки — **игровая модель, не медицинская оценка**. Oura `sleep_balance` — не количество часов недосыпа; оно не используется как долг сна.

Импорт не перезаписывает ранее введённые вручную числа; повторные синхронизации обновляют только пустые или уже полученные ранее из Oura поля. Если пользователь вручную исправляет показатель в LifeSims, следующий импорт больше не заменяет его. Метаданные о происхождении хранятся в `ouraFields`, а дата последнего импорта — `ouraImportedAt`.

## Конфиденциальность и ограничения

- Публичный Client ID хранится локально в браузере; **access token** хранится в `sessionStorage` текущей вкладки и удаляется по завершении сеанса. Он **не** попадает в JSON-резервную копию, исходники или GitHub.
- Числовые показатели здоровья, оценки Oura и происхождение полей сохраняются локально в LifeSims и включаются в пользовательский JSON-бэкап. Не пересылай его посторонним.
- Oura документирует для клиентского OAuth отсутствие refresh token и повторное подключение после истечения access token. Фоновая синхронизация при закрытом приложении требует отдельного серверного компонента и не реализована.
- Данные сна Oura обновляются после синхронизации кольца с приложением Oura. До этого новых данных может не быть.
- Oura deprecated personal access tokens в 2025 году: требуется зарегистрированное OAuth-приложение.
- Реальные авторизация Oura и CORS-доступ к API из опубликованного PWA не протестированы без принадлежащего пользователю Client ID и согласия. При CORS-блокировке необходим безопасный backend-прокси с авторизацией; небезопасный открытый прокси недопустим.
- Никакие данные Oura не используются для выставления диагноза.

## Проверки

- Синтаксис JS для всех встроенных модулей.
- Симуляция агрегации сна: длинный сон 7 ч плюс дневной сон 0,5 ч = 7,5 ч; запись rest не засчитывается.
- Проверка хранения: ранее вручную заданные 8 часов сна не заменяются на 7,5 ч из Oura, а ранее импортированные шаги обновляются.
- При запрете локального хранения импорт останавливается без изменения состояния.
- OAuth callback удаляет токен из URL и отвергает неверный CSRF state; токен не сохраняется в localStorage.

Официальная документация: https://cloud.ouraring.com/docs/authentication и https://cloud.ouraring.com/v2/docs.
