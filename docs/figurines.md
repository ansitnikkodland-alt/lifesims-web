# LifeSims — создание фигурки персонажа по фото (v128, прототип)

## Интерфейс
«Семья → Фигурка»: взрослый выбирает себя или ребёнка, загружает портрет и подтверждает передачу изображения на обработку. После серверной генерации видит предпросмотр и отдельно подтверждает сохранение. Можно скачать или импортировать уже готовую PNG/WebP-фигурку с прозрачным фоном. Исходное фото НЕ сохраняется в БД и не добавляется в прогресс или IndexedDB.

Каждый аккаунт имеет собственную сохранённую фигурку, получаемую через защищённый GET /v1/figurines, а взрослый может управлять фигурками только своих дочерних аккаунтов. Готовая фигурка пока является статичным 2D/WebP-изображением поверх иллюстрированной комнаты, **не 3D-моделью с ригом**. Исходный персонаж нарисован прямо на общем фоне комнаты. Пока не подготовлен фон без встроенного персонажа, возможно наложение двух фигур — проверить на телефонах перед выпуском для детей.

## Активация
Серверный сервис должен использовать ветку, содержащую новый family-api/figurines.mjs и schema.sql. Никаких API-ключей в GitHub, JavaScript и PWA.

- `OPENAI_API_KEY`: только переменная окружения серверного Render-сервиса; отдельная платная API-квота OpenAI.
- `FIGURINE_GENERATION_ENABLED=1`: явно разрешает оплачиваемую генерацию в сервере.
- `FIGURINE_CHILD_UPLOADS_ENABLED=1`: разрешает генерацию/сохранение фигурок детей. **Не включать на временном Render Free PostgreSQL**, срок действия тестовой БД 2026-12-23. Нужны постоянное защищённое хранилище и политика детских данных.

API вызывает POST https://api.openai.com/v1/images/edits с `gpt-image-2.5-sunburst`, запрос `images[0].image_url` с data URL, `background:transparent`, `output_format:webp`. Исходное фото пересылается провайдеру только по явному согласию в интерфейсе, не хранится в LifeSims; хранение данных самим провайдером регулируется его политиками.

Операционные ограничения: 3 попытки генерации за 24 часа на взрослого (лимит приложения в памяти процесса), 1 генерация за запрос, до 1.7 МБ JPEG/PNG/WebP исходного фото. Результат не сохраняется, пока пользователь не подтвердит. Не рассчитывать на этот простой лимит как на финансовую защиту для многосерверного продакшена; нужна централизованная квота и бюджетный лимит у провайдера. Сохранять только с подтверждением о временной базе.

## Проверка
`node --check family-api/figurines.mjs`; `node --check scene/figurines.js`; `node --test family-api/test/figurines.test.mjs`. Обязательные проверки в Android: регистрация и вход ребёнка, отсутствие доступа к чужим фигуркам, качество сходства, правильная прозрачность, позиции и перекрытия, возврат к обычному персонажу после удаления, сохранность старых прогрессов и котиков.

Механизм не является заменой полноценному персональному 3D-аватару.
